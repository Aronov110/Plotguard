# CI for Plotpal (GitHub Actions)

## Goal

Every pull request and every push to `main` runs the checks that were run by hand: lint, both
typechecks, unit tests, integration tests with a real PostgreSQL, the browser tests on Chromium and
WebKit, and the dependency audit. Done means: the first PR runs green on GitHub, each kind of failure
has been shown to turn the run red, and the README describes it.

## Tech choices

GitHub Actions (the repo is public and on GitHub: free and standard). Same stack as locally: Bun 1.4.3
with `--frozen-lockfile`, Node 24 (the lowest the `engines` field allows), `postgres:18.6-alpine` as a
service container. Actions pinned to full commit hashes. No new dependency, no young tools (a workflow
security linter such as `zizmor` was flagged and not adopted).

## Files

`.github/workflows/ci.yml` (jobs `check`, `integration`, `e2e` as a Chromium/WebKit matrix, and the `ci`
gate), `.github/workflows/audit.yml` (audit on PRs, pushes and every Monday), `.github/actions/setup/`
(a local composite action: Bun, Node, cache, locked install, used by every job), `README.md`, this plan.
No application code and no test changes; `retries: 0` in `playwright.config.ts` stays.

## Test plan

Before pushing: actionlint (through Docker) reports nothing. On GitHub: all jobs green on the first PR;
times noted; a second run hits the caches. Proof that it can fail, on a throwaway branch deleted
afterwards: a lint error (`check` red), a failing unit test (`check` red), a failing integration test
(`integration` red), a failing browser assertion (`e2e` red), a `bun.lock` that disagrees with
`package.json` (install fails); the `ci` gate must go red in each case except the browser one (not in the
gate yet). Edge cases: a skipped or cancelled job fails the gate; two quick pushes cancel the older run;
a fork PR has no secrets (`pull_request`, never `pull_request_target`, and no secrets used at all).

## Security and accessibility

`contents: read` only; `persist-credentials: false`; no event text in shell commands; artifacts kept
7 days and only on failure (reports can hold the typed passwords and cookies of throwaway test accounts);
no secrets (the AI tests use the fake model); the database password in the file is a throwaway for a
container that lives for one run. No UI; the browser tests keep running axe on every PR (WCAG).

## Alternatives and risks

Rejected: one big job, another CI service, the hosted Playwright container image. Risks: the known flaky
WebKit tests (hence `e2e` outside the gate for now); Linux versus Windows differences (a real failure
there is a finding); `bun audit` going red through no fault of a PR (hence outside the gate); pinned
hashes going stale (Dependabot, later).
