# The new look and motion

## Goal

A calmer, more modern, animated interface: a focus-first writing screen (AI assistant as a drawer, outline as
a collapsible panel, a large borderless editor), warm light colours, midnight dark colours, richer inputs,
and purposeful motion. Done means: each PR merged with tests green, axe clean in light and dark, 320 px reflow
and keyboard use intact, reduced motion respected, and no behaviour changed.

## Tech choices

Plain CSS and the existing token names (`--color-bg`, …), with new tokens for depth, accent tint, motion and
the second radius. Theme: light values in `:root`, dark values under `prefers-color-scheme`, an explicit
`data-theme` override, and `color-scheme`. Motion in CSS; native View Transitions through React Router for
page changes; no animation library. Fonts self-hosted through `@fontsource-variable/newsreader` and
`@fontsource-variable/dm-sans` (the one flagged new dependency; nothing is loaded from Google at run time).
Icons: an own `Icon` atom with about 15 SVG paths. `light-dark()` was rejected: older Safari lacks it.

## The four PRs

- A, foundation: tokens (light from A, dark from B), fonts, motion tokens, `Icon`, `SegmentedControl`, the theme
  logic and switch (saved as a preference, applied before the first paint by a tiny script), restyled buttons
  and focus, and the contrast test extended to both themes and the forced themes.
- B, the writing screen: header, AI assistant drawer, collapsible outline, borderless editor, animated save pill.
- C, forms and choices: inputs with icons, show-password, animated errors, segmented mode choice, scope cards.
- D, motion: page transitions, items and results that animate in, skeletons, livelier progress, a reduced-motion
  browser test.

## Test plan (all PRs)

Theme logic (system dark and light, override, saved and invalid values, blocked storage, system change);
contrast of every token pair in all three theme blocks and a parity test that the two dark blocks are equal;
drawer behaviour (open and close by button and Escape, focus in and back, hidden when closed, a run goes on,
keyboard only); 320 px reflow; axe in light, dark and both forced themes; reduced motion; existing tests
updated on purpose and listed in each PR; bundle and font weight measured before and after.

## Security and accessibility

The theme preference is harmless and holds no token; the early script is a small file with no input; fonts come
from our own server (no third-party request); fonts pinned and covered by `bun audit`. Drawer: a labelled
complementary region, not a modal, with focus management and 44 px targets; no colour-only signals; motion
stops under reduced motion. Field edges must stay at 3:1 (WCAG 1.4.11): the soft borders of the mockups are
used for dividers only.

## Alternatives and risks

Rejected: a CSS framework or component library, an animation library, the icon-only rail, dark-only, mixing the
two font sets. Risks: PR B restructures the page, so many tests change; the result cannot be seen by the
assistant in a browser (screenshots will be checked, and each PR should be looked at in the owner's browser);
View Transitions fall back to no transition in browsers without them.
