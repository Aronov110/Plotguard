# The new look and motion

## Goal

A calmer, more modern, animated interface: a focus-first writing screen (AI assistant as a drawer, outline as
a collapsible panel, a large borderless editor), warm light colours, midnight dark colours, richer inputs,
and purposeful motion. Done means: each PR merged with tests green, axe clean in light and dark, 320 px reflow
and keyboard use intact, reduced motion respected, and no behaviour changed.

## Tech choices

Plain CSS and the existing token names (`--color-bg`, …), with new tokens for depth, accent tint, motion and
the second radius. Theme: light values in `:root`, dark values under `prefers-color-scheme`, an explicit
`data-theme` override, and `color-scheme`. Motion in CSS; native View Transitions through React Router for
page changes; no animation library. Fonts self-hosted through `@fontsource-variable/newsreader` and
`@fontsource-variable/dm-sans` (the one flagged new dependency; nothing is loaded from Google at run time).
Icons: an own `Icon` atom with about 15 SVG paths. `light-dark()` was rejected: older Safari lacks it.

## The four PRs

- A, foundation: tokens (light from A, dark from B), fonts, motion tokens, `Icon`, `SegmentedControl`, the theme
  logic and switch (saved as a preference, applied before the first paint by a tiny script), restyled buttons
  and focus, and the contrast test extended to both themes and the forced themes.
- B, the writing screen: header, AI assistant drawer, collapsible outline, borderless editor, animated save pill.
- C, forms and choices: inputs with icons, show-password, animated errors, segmented mode choice, scope cards.
- D, motion: page transitions, items and results that animate in, skeletons, livelier progress, a reduced-motion
  browser test.

## Test plan (all PRs)

Theme logic (system dark and light, override, saved and invalid values, blocked storage, system change);
contrast of every token pair in all three theme blocks and a parity test that the two dark blocks are equal;
drawer behaviour (open and close by button and Escape, focus in and back, hidden when closed, a run goes on,
keyboard only); 320 px reflow; axe in light, dark and both forced themes; reduced motion; existing tests
updated on purpose and listed in each PR; bundle and font weight measured before and after.

## Security and accessibility

The theme preference is harmless and holds no token; the early script is a small file with no input; fonts come
from our own server (no third-party request); fonts pinned and covered by `bun audit`. Drawer: a labelled
complementary region, not a modal, with focus management and 44 px targets; no colour-only signals; motion
stops under reduced motion. Field edges must stay at 3:1 (WCAG 1.4.11): the soft borders of the mockups are
used for dividers only.

## Alternatives and risks

Rejected: a CSS framework or component library, an animation library, the icon-only rail, dark-only, mixing the
two font sets. Risks: PR B restructures the page, so many tests change; the result cannot be seen by the
assistant in a browser (screenshots will be checked, and each PR should be looked at in the owner's browser);
View Transitions fall back to no transition in browsers without them.

## PR B (the writing screen, `feat/writing-screen`)

Status: approved (2026-11-14), decisions taken as recommended ("a for all"): on narrow screens the AI drawer
sits below the text (no overlay, no focus trap); the editor keeps a thin visible border (3:1) instead of
being borderless; the outline panel is open by default on wide screens; open or closed is not remembered
(the theme is the only saved preference).

Built from: a project bar (back link, project title, Outline and AI assistant toggle buttons with
`aria-expanded` and `aria-controls`); a grid of three columns (outline, text, AI drawer) whose outer widths
animate between 0 and a fixed width; below 60 rem one column, with the outline and the drawer opening by
height; the drawer is a labelled non-modal `aside` (`Drawer` molecule): opening moves the focus to its
heading, Escape or Close shuts it and returns the focus to the toggle, closed it is `inert` and hidden;
`AiPanel` loses its disclosure button and gets an `open` prop (a run goes on while it is closed; nothing
loads before the first opening); the editor becomes a paper surface; the save status becomes an animated
pill that still says its state in words.

### Outcome of PR A (the foundation, `feat/design-foundation`, merged as #31)

Done as planned. Tokens for light (warm paper) and dark (midnight) in three blocks, with `tokens.test.ts`
checking every colour pair in all three and that the two dark blocks are equal; Newsreader and DM Sans as
self-hosted variable fonts (about 95 KB for an English page); the theme logic and switch (System / Light /
Dark, one word in `localStorage`, put on the page before the first paint by `public/theme-init.js`);
`Icon`, `SegmentedControl`, restyled buttons and header. Web unit tests 2,086 -> 2,242; 15-way mutation check,
all caught; browser: 464 passed, 2 skipped. Found by the tests: the hidden radio buttons of the segmented
control must take the click themselves (a `pointer-events: none` one could not be clicked by a browser
test). Two things the mockups got wrong for accessibility and were changed on purpose: field edges use the
strong `--color-border` (3:1), the faint colour is `--color-divider` for decoration only.

### Outcome of PR B (the writing screen, `feat/writing-screen`)

Done as planned, with the four decisions as recommended. Built: `Drawer`, `ProjectBar`, the three-column
`WritingPage` (outer columns animate; below 60 rem one column, the drawer below the text), `AiPanel` with an
`open` prop (it stays mounted when closed, so a run goes on; it loads only after the first opening and does
not load again on reopening), the paper editor, the animated save pill, the restyled outline and toolbar.
Closed panels are `inert` and hidden.

- Tests: web 2,242 -> 2,295 (new: Drawer, ProjectBar, the page's panels, the save pill); 18 new browser tests
  on each browser (`writing-screen.e2e.ts`: toggles, focus in and back, Escape, nothing closed can be
  tabbed to, a run goes on while closed, 320 px without sideways scroll, reduced motion, axe in light, dark
  and on a phone). Full browser run: 500 passed, 2 skipped. Lint, both typechecks clean.
- Found by the tests: axe flagged the drawer column as a scrollable region without keyboard access while it

- Mutation check: 16 breaks, 15 caught. The one that survives (Escape closing an already closed drawer) is
  unreachable: a closed drawer is `inert`, so the guard is redundant defence. A gap found by the check
  (nothing proved that closing and reopening does not reload the cost and history) got its own test.
- Not verified: how it feels in the owner's browser (checked by screenshots only); old Safari shows the
  drawer without sliding. The AI panel's own radio groups still have their old look (PR C).
